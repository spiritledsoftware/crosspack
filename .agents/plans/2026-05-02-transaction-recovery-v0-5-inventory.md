## Status Policy Matrix

| Status | Active marker expected | Recovery policy target | Gap | Owner | Test target |
|---|---|---|---|---|---|
| `planning` | Yes during active transaction | Safe to clear/finalize only after deterministic classification | Covered by coordinator classification and repair tests | Task 5/9 | Recovery classification matrix |
| `applying` | Yes | Fail closed or resume rollback depending on payload completeness | Covered by coordinator classification, repair, and rollback tests | Task 5/9 | Recovery classification matrix |
| `completed` | Usually no; legacy terminal status | Treat as terminal-compatible committed state | Covered by legacy terminal classification | Task 5 | Legacy completed classification |
| `committed` | No after clear | Terminal clean state | Covered by durable clear and stale-marker cleanup tests | Task 4/5/9 | Active clear and classification tests |
| `rolling_back` | Yes while rollback active | Resume rollback or fail closed if payload missing | Covered by coordinator repair and rollback evidence tests | Task 5/9 | Rollback recovery classification |
| `rolled_back` | No after clear | Terminal clean state after rollback cleanup | Covered by rolled-back classification and clear tests | Task 5/9 | Rolled-back classification |
| `failed` | Yes or marker retained for repair | Require repair/rollback decision with reason code | Covered by repair action diagnostics and orphan failed repair test | Task 5/11 | Failed transaction diagnostics |
| Missing metadata with active marker | Yes | Fail closed and report repair-required | Covered by repair-required classification and preflight/doctor diagnostics | Task 5/10/11 | Missing metadata classification |
| Metadata without active marker | No | Fail closed for non-terminal mutating statuses | Covered by orphan metadata classification and repair tests | Task 5/9 | Orphan metadata classification |
| Corrupt journal or metadata | Any | Fail closed with parse context | Covered by journal read/parse and metadata JSON hardening tests | Task 6/9 | Corrupt journal parse test |

Every gap above has an owner and test target. Tasks 1-4 address metadata format lock-in, durable filesystem primitives, journal append durability, and active marker clear durability. Task 7 uses begin crash hooks only: broader lifecycle crash hooks would require test-only seams through CLI orchestration, artifact install, exposure cleanup, native cleanup, and uninstall flows, while Task 8 now covers the practical payload-before-mutation and rollback replay invariants directly. Tasks 9-11 close deterministic recovery execution, fail-closed preflight routing, repair action diagnostics, transaction detail output, and metadata txid mismatch handling. Directory sync, empty-directory pruning, native cleanup warnings, and cache pruning remain best-effort by policy rather than rollback payload surfaces. No unresolved v0.5 hardening gaps remain in this inventory.
